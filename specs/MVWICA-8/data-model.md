**Branch**: `MVWICA-8` | **Date**: 2026-08-12

## Entities

### 1. TemperatureReadingEvent (Kafka / Avro)

Published to topic `health-metrics.temperature` by `sapphire-event-ingestion-api`.

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `event_id` | string (UUID) | ✅ | Generated by ingestion service; idempotency key |
| `user_id` | string (UUID) | ✅ | Platform user identifier |
| `measured_at` | string (ISO-8601) | ✅ | Original device measurement timestamp |
| `ingested_at` | string (ISO-8601) | ✅ | Server-side ingestion timestamp |
| `value` | double | ✅ | Temperature reading value |
| `unit` | enum {`CELSIUS`, `FAHRENHEIT`} | ✅ | Submitted unit, preserved as-is |
| `device_source_id` | string | ✅ | Device or partner API identifier |
| `ingestion_source` | string | ✅ | e.g., `"api"`, `"batch"` |
| `measurement_method` | string | ❌ | Optional: e.g., `"oral"`, `"axillary"`, `"tympanic"` |

**Validation rules**:
- `value` CELSIUS: 25.0 – 45.0 (configurable via `TEMP_RANGE_MIN_C` / `TEMP_RANGE_MAX_C`)
- `value` FAHRENHEIT: 77.0 – 113.0 (configurable via `TEMP_RANGE_MIN_F` / `TEMP_RANGE_MAX_F`)
- `measured_at` must not be more than 5 minutes in the future relative to `ingested_at`
- `measured_at` may be arbitrarily in the past (historical buffered readings accepted)

### 2. temperature_readings (PostgreSQL / TimescaleDB hypertable)

Persisted by `sapphire-kafka-pipeline` Kafka Connect sink.

```sql
CREATE TABLE temperature_readings (
    event_id            UUID        NOT NULL,
    user_id             UUID        NOT NULL,
    measured_at         TIMESTAMPTZ NOT NULL,   -- partition key (time dimension)
    ingested_at         TIMESTAMPTZ NOT NULL,
    value               DOUBLE PRECISION NOT NULL,
    unit                VARCHAR(11) NOT NULL,   -- 'CELSIUS' | 'FAHRENHEIT'
    device_source_id    VARCHAR(255) NOT NULL,
    ingestion_source    VARCHAR(50) NOT NULL,
    measurement_method  VARCHAR(50),
    PRIMARY KEY (event_id, measured_at)
);

SELECT create_hypertable('temperature_readings', 'measured_at',
    chunk_time_interval => INTERVAL '1 day');

CREATE INDEX idx_temperature_readings_user_time
    ON temperature_readings (user_id, measured_at DESC);
```

### 3. temperature_rollups (PostgreSQL / TimescaleDB continuous aggregate)

Materialised daily aggregates; queried by `sapphire-charting-api` for week/month views.

```sql
CREATE MATERIALIZED VIEW temperature_daily_rollups
WITH (timescaledb.continuous) AS
SELECT
    user_id,
    time_bucket('1 day', measured_at)   AS bucket,
    unit,
    MIN(value)                          AS min_value,
    MAX(value)                          AS max_value,
    AVG(value)                          AS avg_value,
    COUNT(*)                            AS record_count
FROM temperature_readings
GROUP BY user_id, time_bucket('1 day', measured_at), unit
WITH NO DATA;

SELECT add_continuous_aggregate_policy('temperature_daily_rollups',
    start_offset => INTERVAL '3 days',
    end_offset   => INTERVAL '1 hour',
    schedule_interval => INTERVAL '1 hour');
```

### 6. TemperatureAlertEvent (Kafka — alert topic)

Published by `sapphire-kafka-streams-consumer` when a threshold is breached.

| Field | Type | Notes |
|-------|------|-------|
| `alert_id` | string (UUID) | Generated |
| `user_id` | string (UUID) | From source reading |
| `triggered_at` | string (ISO-8601) | Processing time |
| `reading_value` | double | The breaching value |
| `reading_unit` | string | CELSIUS or FAHRENHEIT |
| `threshold_type` | enum {`HIGH`, `LOW`} | Which threshold was breached |
| `threshold_value` | double | The configured threshold |
| `device_source_id` | string | From source reading |

## State Transitions

### TemperatureReadingEvent lifecycle

```
Device POST
    → [Validation] → REJECTED (HTTP 422) if out-of-range / missing fields / future timestamp
    → [Rate check]  → REJECTED (HTTP 429) if per-key limit exceeded
    → [Auth check]  → REJECTED (HTTP 401) if invalid API key
    → [Kafka down]  → REJECTED (HTTP 503) if broker unavailable
    → PUBLISHED to health-metrics.temperature topic
        → PERSISTED to temperature_readings hypertable (via Kafka Connect, ≤10s)
            → AGGREGATED into temperature_daily_rollups (continuous aggregate, ≤1h lag)
                → [Alert check] → ALERT published to alert topic if threshold breached
```

## Relationships
